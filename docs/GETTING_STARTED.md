# 从零安装 BEC 自动化

这份指南面向第一次使用本仓库的玩家。当前对外安装入口是 **V2 独立测试版**，适配目标为 GTNH 2.9.0 Beta 3 + OpenComputers/OpenOS。不同版本的BEC/OC方法可能不同；向导会检查设备实际提供的方法。

## 1. 下载哪些文件

推荐直接使用安装器。电脑需要能访问GitHub的互联网卡、OpenOS的wget和足够磁盘空间。在**游戏里的OC电脑终端**执行：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/bec-v2-preview-2026-10-09/experimental/bec_v2/install.lua /home/bec_v2_install.lua
lua /home/bec_v2_install.lua
```

安装器只写 `/home/bec_v2/` 下的程序文件，不操作机器、转换样板或下单，不覆盖已有配置、配方和日志。升级前先退出V2服务。

没有互联网卡时，下载 [V2安装包](https://github.com/Alivn-chao/gtnh-bec-automation/releases/download/bec-v2-preview-2026-10-09/bec_v2_multinode.zip)。将包内 `bec_v2` 目录按下表放入游戏电脑；也可以使用包内 `paste` 的同名紧凑文件，每个文件不超过257行，逐个 `edit` 粘贴，Ctrl+S保存、Ctrl+W退出。

| 游戏电脑路径 | 必须下载的文件 | 用途 |
| --- | --- | --- |
| `/home/bec_v2/` | `main.lua` | 全部命令的入口 |
| `/home/bec_v2/lib/` | `config.lua`、`setup.lua` | 保存配置、扫描选择设备、扩容 |
| `/home/bec_v2/lib/` | `bridge.lua`、`engine.lua` | 同配方物理并行、分组、多纠缠器 |
| `/home/bec_v2/lib/` | `ui.lua`、`scan.lua`、`patterns.lua` | 仪表盘、查地址、样板处理入口 |
| `/home/bec_v2/runtime/` | `controller.lua`、`nanites.lua`、`patterns.lua` | 补液、蜂群切换、样板转换核心 |

手动粘贴前建立目录：

```sh
mkdir /home/bec_v2
mkdir /home/bec_v2/lib
mkdir /home/bec_v2/runtime
edit /home/bec_v2/main.lua
```

其余文件分别编辑对应路径。不要把 `paste/lib` 整体放进游戏的 `/home/bec_v2/paste/lib`；应使用其中的文件覆盖上述相同目标路径。

仓库根目录的 `bec_auto.lua` 等文件是早期单节点快照，含作者的历史地址。新用户按这份指南安装V2即可；不必下载旧测试脚本、截图、Python文件或旧快照ZIP。

## 2. 要准备什么

- 一台OC电脑或服务器，GPU和屏幕至少支持80×25字符，足够内存、磁盘和组件容量。组件多时增加服务器/组件容量；配置扫描必须能看到全部设备。
- 1至16台传送节点，节点的控制仓设置为**立即暂停**。
- 每个节点的OC适配器，用于读取状态、需求、并行和已消耗量；红石I/O负责给对应控制仓输出暂停信号。红石I/O不能代替状态适配器。
- 每个设备组至少一个约束场、一个麦克斯韦门、一台纠缠器，以及各设备的OC适配器。纠缠器可以增加多台。
- 主网供液ME接口、独立原液子网的接收ME接口、两者之间的OC转运器。
- 专用工坊ME接口用于处理原加工样板副本；生产ME接口用于下发转换后的样板。
- 自动换蜂群时再准备蜂群转运器、备用蜂群网ME接口、收容总线子网ME接口。

约束场始终保持开启。OC需要供电，所有适配器、转运器和红石I/O接到同一个可见的OC组件网络；可以用已正常工作的OC P2P延长距离。AE网络是否独立与OC组件线是否相连是两回事。

## 3. 怎么布置

### 原液路线

```text
AE主网（有原液库存和可合成的原液配方）
  → 主网供液ME接口
  → OC转运器精确搬液
  → 本组原液子网ME接口 + 流体存储
  → 纠缠器的进阶存储输入仓（ME）
  → 本组约束场 / BEC网络
  → 麦克斯韦门过滤
  → 本组传送节点
```

转运器紧邻两个接口，记下两个接口相对于转运器的方向。原液子网必须与主网独立：程序控制有限量原液进入，纠缠器只看到已搬入的本组原液。不要用存储总线把主网全部原液直接暴露给这个子网。该路线不需要外部储罐。

多台纠缠器接入同组原液供应和BEC网络；向导为每台绑定地址，程序一起启停并逐台回读。同组共享一个约束场读数、韦门过滤和蜂群；不同独立BEC网络才配置为不同设备组。

### 普通物品与成品路线

```text
主网生产ME接口中的已转换加工样板
  → 普通物品投料路线 / 物品子网的存储缓冲
  → 对应传送节点的进阶存储输入总线（ME）
  → 合成
  → 节点输出总线（ME）
  → 主网回收成品
```

物品子网要有物品存入位置，流体存储元件不能代替物品缓冲。生产接口使用已验证的高级阻挡卡及智能阻挡模式。多节点的物理投料路线须能让每台接到同一个配方；V2会汇总当前已经接单的同配方节点一起放行，未接单的节点不会凭空被算进本批次。图示可参考 [已有物理布局](https://github.com/Alivn-chao/gtnh-bec-automation/blob/main/evidence_layout.png)，实际设备名称以上述路线为准。

### 蜂群路线

```text
备用蜂群AE网（存储各等级蜂群）
  → 专用ME接口 ┐
               ├ OC转运器桥接普通物品
  → 专用ME接口 ┘
收容总线AE子网 → 存储总线 → 蜂群收容仓
```

转运器紧邻这两个普通物品ME接口；使用存储总线提供的读写仓能力，不直接搬显示槽。收容子网只暴露本组蜂群仓，接口配置栏保持空白；存储总线允许插入和提取，蜂群仓显示/输出槽保持锁定。备用网与收容网独立，ME接口自动接收搬来的物品。

同组全部传送节点共用这些蜂群，切配方只切换一次；显示的蜂群数量是共享值，不把各节点读数相加。不同组不要共用同一个蜂群控制接口。暂时不搭蜂群网时，向导选择关闭自动换蜂群，手动提供合适等级和数量的蜂群。

## 4. 地址在哪看

安装完成后运行只读扫描：

```sh
lua /home/bec_v2/main.lua scan
```

扫描会列出设备类型、OC组件地址，并列出转运器各面的相邻库存。绑定时可选扫描列表的序号，或输入足以唯一识别的地址前缀；不需要把完整UUID反复抄进脚本。

| 向导里要填的角色 | 扫描中的组件类型 | 应对应哪个实物 |
| --- | --- | --- |
| 主网/原液子网/蜂群接口 | `me_interface` | 该网络的ME接口，须通过适配器可读 |
| 工坊样板接口 | `me_interface` | 单独用来转换样板的接口，不是生产接口 |
| 传送节点 | `bec_io_node` | 对应节点适配器暴露的组件 |
| 约束场 | `bec_storage` | 本组约束场适配器 |
| 韦门 | `bec_diode` | 本组麦克斯韦门适配器 |
| 纠缠器 | `gt_machine` | 名称须是 `multi.bec.generator` |
| 搬液/搬蜂群设备 | `transposer` | 对应OC转运器 |
| 暂停控制 | `redstone` | 控制该节点控制仓的OC红石I/O |

有多个同类设备分不清时，在生产已停止后，临时断开其他同类设备的OC连接，再扫描比对。也可查看游戏中设备/适配器的OC提示：使用其中的**组件类型与组件地址**，不是坐标、AE频道或机器物品ID。仓库截图中的作者地址不适用于你的存档。

方向统一为：`0下、1上、2北、3南、4西、5东`，以转运器或红石I/O自身为参照。最容易确认的接法是红石I/O放在控制仓下方，向上 `1` 输出：`15`立即暂停，`0`放行。多个节点可以共用一个红石I/O的不同输出面，但不能重复绑定同一“地址+方向”；节点状态适配器仍每台单独接。

## 5. 配置、登记配方和启动

首次配置：

```sh
lua /home/bec_v2/main.lua setup
```

按顺序选择：节点总数 → 设备组数 → 主网接口 → 配方目录 → 工坊接口 → 每组的场、韦门、原液子网、转运器及方向、纠缠器列表、蜂群路线 → 每台节点及暂停线路。一般一个共享BEC网络选 **1组**；它里面可以有16台节点和多台纠缠器。

新用户的配方目录直接回车采用 `/home/bec_v2/recipes`；已有用户可填现有 `/home/bec/recipes`。配置保存到 `/home/bec_v2/config.dat`，不改程序源码。

首次生产前，将**原加工样板副本**放进工坊接口的9个样板槽。先预览，再转换登记：

```sh
lua /home/bec_v2/main.lua patterns preview
lua /home/bec_v2/main.lua patterns run
```

预览只读；`run`会保存凝聚物需求、移除样板末尾的凝聚物流体输入并核对结果。转换后的样板仍在工坊接口，手动移到生产ME接口。已经去掉流体、又没有原始需求记录的样板不能靠程序猜出需求，需要原样板副本重新登记。支持单产物加工样板；NBT产物、交错流体输入或冲突记录会停止核对。

先检查只读仪表盘：

```sh
lua /home/bec_v2/main.lua monitor
```

确认设备显示在线，退出任何旧控制服务，把节点暂停信号置15、纠缠器关闭并等它停止活动，保持约束场开启，然后：

```sh
lua /home/bec_v2/main.lua run
```

先下一个已登记配方的小订单，再测试2台同配方物理并行，最后扩到更多节点。原液缺货时，主网须有对应原液的AE合成能力。材料名称没有已知映射或配方未登记时，程序暂停核对，不猜测投料。

| 生产界面按键 | 操作 |
| --- | --- |
| ↑ / ↓ | 选择节点 |
| P | 暂停所选节点所在整组 |
| R | 核对现场后恢复整组；恢复检查仍会拒绝未确认操作 |
| A | 暂停全部 |
| N | 凝聚物库存翻页 |
| Q | 暂停全部节点、关闭纠缠器并退出程序 |

只读监控中Q只退出监控，不操作机器。V2现在显示库存参考条并按当前批次补液；固定目标后台预缓存和可编辑缓存页仍在旧版，不能同时对同一组设备运行旧、新两个控制服务。

## 6. 以后添加节点或纠缠器

添加节点时先让当前批次正常完成，Q退出。按第3节接好新节点、状态适配器、投料/成品路线和暂停红石I/O，再执行：

```sh
lua /home/bec_v2/main.lua add-nodes
```

填扩容后的**总数量**，例如原来2台、再加2台就填4。只为新增节点选名称、现有设备组、节点地址、红石I/O和方向，原有地址、纠缠器列表、原液与蜂群配置保留。保存后先 `monitor` 再 `run`。新节点须手动处于暂停信号15。上限16台。

新增节点仍共享原BEC网络/蜂群时选原设备组；重新搭了一套独立BEC网络时使用 `setup` 全量配置新组。增加纠缠器也使用 `setup` 重配该组的纠缠器数量和列表；配置向导目前全量重绑，按 [配置示例](https://github.com/Alivn-chao/gtnh-bec-automation/blob/bec-v2-preview-2026-10-09/experimental/bec_v2/config.example.lua) 事先记好角色。

有未完成或异常中断批次时，配置向导会拒绝改绑定。先用原配置核对恢复，不能删除日志绕过检查，也不要给旧进度换到另一台机器。

## 7. 常见问题

| 提示/现象 | 检查 |
| --- | --- |
| 找不到组件 | 适配器、OC线/P2P、组件容量、供电；不是只连接AE线 |
| 设备缺少方法 | 绑定角色错误，或服务器模组版本不提供需要的方法 |
| 地址不唯一 | 输入更多地址字符，或选择列表序号 |
| 暂停线路重复 | 同一红石I/O的相同输出面只能用于一个节点绑定 |
| 节点不适合启动 | 控制仓设立即暂停、信号15；查看供电与装配机连接 |
| 未登记需求/不支持凝聚物 | 检查原样板登记、配方目录与原液映射；未知类型不会自动猜 |
| 超过3种多余凝聚物 | 检查韦门结构、供电与过滤回读，避免把额外凝聚物直接暴露给节点 |
| 蜂群数量与收容网不符 | 控制子网仅连接该蜂群仓，检查存储总线读写权限和显示槽锁定 |
| 未确认搬运/下单 | 保留日志和现场，先核对库存、申请结果，不删除日志重跑 |
| 仪表盘闪烁 | 使用支持VRAM的GPU；V2缓冲整帧提交需要可分配的显存 |

运行逻辑已有Lua 5.2模拟验证，包括16台同批放行、组内暂停、多纠缠器回读失败与恢复保护。V2仍需玩家在自己的游戏硬件上逐步验收。
