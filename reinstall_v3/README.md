# V3 第一阶段提速预览

分支 `codex/bec-v3-performance`，基于 V2 网页版 `a293a34`。重点缩短配方读取、换蜂检查和库存充足订单的开工等待。已通过 Lua 5.2 模拟，部分修复已通过 MCP 部署并验证；下方性能数据仍是模拟结果。

## 阶段追赶停住（2026-10-26）

修复同配方节点进度相差多个阶段时的选蜂：追赶节点的需求从本批已缓存的原生
`getRecipeSteps` 和现有进度读取中取得，不再沿用代表节点的上一种蜂群。
蜂群检查使用同一份追赶需求。整组暂停/放行后重新建立先行节点的暂停状态；
追赶完成后，即使蜂群种类无需变化，也正常重新核对并放行。

没有增加每轮逐台读取蜂群需求或配方身份；沿用代表节点检测，完成时保留真实消耗
证明。另提供显式的已就绪批次恢复参数 `engine(cfg,C,Bridge,false,'ready')`：
仅在启动时核对一次原 `ready` 盘批次、生产组、配额、消耗和物理盘位置，构造时不
写盘、不搬盘、不重新接单。普通启动仍拒绝未核对的未完成批次；不明回执保持保留。

232 项回归与 20 个核心模拟场景通过，包含现场 8 台的旧版死锁复现、多阶段追赶、
同蜂群重新放行及已就绪批次恢复。实际安装和验收记录见 `HANDOFF.md`。
这四个配套模块属于已部署的原料盘模式；旧三文件 `update.lua` 不是该模式的完整安装器。

## 网页旧故障与新进度交替显示

2026-10-21 实机捕获到同一 OC 的两套网页状态交替发布：旧实例固定 `fault / 18.75s`，新实例仍在备料/运行。旧故障实例没有退出，恢复时又启动了一套，导致画面往返跳动。

`web.lua` 现在在创建会话、发布页面和执行启动操作之前取得同一面板的单实例锁。重复启动会提示“BEC 网页程序已经运行”，不会释放现有面板或暂停正在工作的机器；正常退出、初始化失败都会释放锁，已结束的协程不会留下永久锁。锁存于 OpenOS 共用的组件代理，重启电脑后自然清除。只读现场状态及完整日志可从代理 `_becWebOwner.state/logs` 读取，供 MCP 诊断。

本次已通过 MCP 直接安装并恢复单实例运行。实机重复启动验证被拒绝、原会话继续生产；模拟另覆盖重复启动、退出后重开、死实例及初始化失败重试。更新包仍使用下方 `update_cache_response.lua`，兼容第一轮响应修复 `499d433`。已有两套旧程序时先正常 Q 退出全部实例、确认工作器已收尾；不要在搬盘途中断电，保留未确认记录。

## 缓存翻页、保存慢的追加修复

已装第一轮 V3 的用户，使用下面的追加更新包。第一轮 `update.lua` 只更新生产/蜂群模块；本包另更新网页及五个配套 Lua 文件，无需重装或重新绑定。

在 **OC 按 Q 正常退出**当前网页程序，回到 OpenOS 执行（如果在 `lua>`，先 Ctrl+D）：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/codex/bec-v3-performance/reinstall_v3/update_cache_response.lua /home/bec_v3_cache_update.lua
lua /home/bec_v3_cache_update.lua
lua /home/bec_v2/main.lua web
```

- **翻页本地完成**：快照包含紧凑目录，首次打开下一页也无需等待 OC 扫配方；输入草稿和正在保存的状态保留。目录过大、接近面板 512 值/16 KiB 快照上限时回退到快速分页请求。
- **保存不再排在整轮补库后**：原来长循环只收请求、回复“已收到”，实际处理要等循环返回。现在缓存值保存、分页与暂停可在后台组件读取的间隙处理；启动和绑定修改仍走原队列，不嵌套处理器。单个 OC 回调或磁盘写入本身仍需等待。
- **成功仍代表确实落盘**：保留版本冲突、空间检查、flush 与回读验证，保存失败显示失败；运行中的补库在本轮结束后使用新目标。不会因超时自动重发保存或机器操作。

本包识别第一轮 V3 `0e3926a` 的六个目标文件（最新 V2 `a293a34` 的这六文件相同），也支持已安装第一轮响应修复 `499d433` 和 `2e3dc3c`。未知本地版本拒绝覆盖。配置、地址、配方及所有运行日志保留；更新器不操作机器。六个旧文件备份为 `.before-v3-cache-N`，替换失败整套回滚；更新仍需临时文件空间并留出 512 KiB。回退须成套恢复六个程序，保留运行记录。

模拟复现：旧版在 180 次、每次 0.2 模拟秒的读取过程中一直排队；新版在首个读取边界落盘并在 1 模拟秒内返回完成结果。真实缓存工作器的配方日志边界、冲突/flush 失败、队列顺序、防嵌套、待发送回执、目录大小以及十二个替换位置故障回滚均已覆盖。**这是模拟结果，实际游戏响应时间待复测。** 复测可在补库读配方时首次翻页、保存单项目标，并重开网页核对保存值。

## 暂停与固定信息复用（2026-10-25）

暂停请求可在读取间隙响应，并立即通知缓存收尾。配方流体目录和产物索引与网页目录共用，样板处理或手动刷新后失效，重启时只读一次。已确认的高速供液口位置与原液别名按组落盘，正式绑定不变时重启也复用；使用前只探测所需口，端口变化才重新发现。库存、操作回执、配方及停机证明仍实时检查。

实际OC已安装并保持暂停，独立工坊两槽样板只读预览成功；补库多轮复用、端口变化、空口、重新启动及错误持久化信息等通过模拟验证。详见 `fixes/pause_response` 与 `fixes/cache_discovery`。不把模拟调用次数称为实机耗时。

- **批次配方索引**：每个工作器首次校验时读取登记文件并索引，之后内存匹配。新批次和恢复创建新工作器，重新加载；网页原有生产/样板互斥保持。生产期间不要用外部程序直接修改配方文件。
- **库存命中快速开工**：凝聚物已满足本批、子网无原液、没有未确认申请/搬运时，跳过供液口发现、原液稳定等待和纠缠启动。放行前再次核对库存、子网、接口、过滤和订单；释放共享供液锁，防止阻塞其他组。
- **蜂群检查去重**：初始检查合并整组暂停/纠缠器停机和共享蜂群确认，控制器沿用蜂群模块已验证的阶段需求。沿用现有蜂群时不搬盘；仍检查盘库、两只 IO 全槽、共享仓和旧日志，仍自动补充新放入的同类蜂群。饱和读数不能当作精确数量，未完成搬盘不重放。

保留独立供液子网、原地址、配置、登记配方、状态日志与恢复入口。V3 源码暂时仍位于 `reinstall_v2/files/`，游戏目录仍是 `/home/bec_v2/`，这次不迁移数据目录。仓库既有 V2 安装器和历史更新包保持原版；**试用本分支先使用本目录的 `update.lua`，再安装上面的 `update_cache_response.lua`，不要用旧安装器覆盖 V3**。本轮不含流水补液、下一单预取或自动均分订单。

## 已有 V2 网页版升级

更新器识别 `a293a34`、`07522a8` 对应的三个目标模块，并核对配套 engine/config。其他本地修改或缺失模块会明确拒绝，不覆盖。无需更换 OCHD 客户端。

1. 在 OC 按 **Q**，正常退出网页运行程序并暂停机器。若在 `lua>` 解释器，先 Ctrl+D 返回 OpenOS。
2. 下载并运行约 78 KiB 的三文件更新包：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/codex/bec-v3-performance/reinstall_v3/update.lua /home/bec_v3_update.lua
lua /home/bec_v3_update.lua
lua /home/bec_v2/main.lua web
```

更新器写临时文件、flush、回读后备份替换，任一替换失败回滚三个程序。检查更新空间并保留至少 512 KiB，支持没有 collectgarbage 的 OpenOS；临时安装包无法删除不阻止更新。不控制机器，不删除配方、配置或任何运行日志。

旧程序备份为各目标文件的 `.before-v3-performance-N`，三文件必须成套恢复，不能只恢复控制器。保留升级后形成的运行日志，不能通过删日志回退现场。若已有未确认搬运/申请，重新打开后仍由原恢复核对决定能否运行。

## 模拟结果及边界

对比对象是升级前 V2 `a293a34`，不是更早的慢版本。

| 场景 | V2 | V3 |
| --- | ---: | ---: |
| 16 节点、库存充足，从接单到收尾的节点读取次数 | 7,323 | 2,710 |
| 两个不同登记配方、两个批次，配方文件读取次数 | 174 | 4 |
| 16 节点已装蜂群的沿用检查，组件调用次数 | 219 | 185 |
| 库存充足测试场景首次放行，模拟秒 | 6.5 | 0.5 |

这些时间来自组件调用耗时为零、调度每 0.1 秒推进的模拟；不能当作实机开工时间或整体提速倍数。最后一行主要反映移除固定等待。实际受 OC 回调、磁盘、TPS、真实换盘以及配方耗时影响。[库存命中原始计数](evidence/stock-hit.json)。

复现：Python 3.12 + `lupa`（Lua 5.2）及 `rjsmin`，运行 `python reinstall_v3/run_tests.py`。脚本重建网页和两个 V3 更新器，然后执行 220 项针对性测试及 20 个原核心场景。网页测试运行 `node reinstall_v2/tests/test_web_control.cjs`，41 个场景通过。覆盖多节点、阶段换蜂、代表节点选择及进度等待、完成瞬间、恢复、不明回执不重放、缓存让位、库存/接口/配方突变、共享锁、网页单实例，以及两个更新器各替换位置失败回滚。历史 V2 安装包测试不在本轮范围，历史包内容没有重建。

实机先使用一个便宜配方，比较库存充足且同蜂群、需要换蜂、需要补液三种情况。关注“蜂群检查/换盘完成”耗时、是否出现“无需搬液和纠缠”、从接单到第一件产物的时间。新增的快速路径仍须真实游戏验证。
