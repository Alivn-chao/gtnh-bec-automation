本次缓存持锁期间关闭节点新接单许可；若订单恰在最后一次idle检查与关闭许可间进入，加载缓存运行器、写缓存日志、搬液或AE下单之前直接交回控制权。原AE队列生产优先检查仍保留，已申请/搬入原液按旧守恒流程收尾；暂停信号、节点状态、外部重开接单和未确认操作保护不移除。

## 缓存翻页、保存慢的追加修复

已装第一轮 V3 的用户，使用下面约 **46 KB** 的小更新包。第一轮 `update.lua` 只更新生产/蜂群模块；本包另更新网页及四个配套 Lua 文件，无需重装或重新绑定。

在 **OC 按 Q 正常退出**当前网页程序，回到 OpenOS 执行（如果在 `lua>`，先 Ctrl+D）：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/codex/bec-v3-performance/reinstall_v3/update_cache_response.lua /home/bec_v3_cache_update.lua
lua /home/bec_v3_cache_update.lua
lua /home/bec_v2/main.lua web
```

- **翻页本地完成**：快照包含紧凑目录，首次打开下一页也无需等待 OC 扫配方；输入草稿和正在保存的状态保留。目录过大、接近面板 512 值/16 KiB 快照上限时回退到快速分页请求。
- **保存不再排在整轮补库后**：原来长循环只收请求、回复“已收到”，实际处理要等循环返回。现在仅缓存值保存和分页可在后台组件读取、配方扫描日志的间隙处理；机器控制、绑定修改等仍走原队列，不插入工作器。单个 OC 回调或磁盘写入本身仍需等待。
- **成功仍代表确实落盘**：保留版本冲突、空间检查、flush 与回读验证，保存失败显示失败；运行中的补库在本轮结束后使用新目标。不会因超时自动重发保存或机器操作。

本包识别第一轮 V3 `0e3926a` 的五个目标文件（最新 V2 `a293a34` 的这五文件相同）。未知本地版本拒绝覆盖。配置、地址、配方及所有运行日志保留；更新器不操作机器。五个旧文件备份为 `.before-v3-cache-N`，替换失败整套回滚；更新仍需临时文件空间并留出 512 KiB。回退须成套恢复五个程序，保留运行记录。

模拟复现：旧版在 180 次、每次 0.2 模拟秒的读取过程中一直排队；新版在首个读取边界落盘并在 1 模拟秒内返回完成结果。真实缓存工作器的配方日志边界、冲突/flush 失败、队列顺序、防嵌套、待发送回执、目录大小以及十个替换位置故障回滚均已覆盖。**这是模拟结果，实际游戏响应时间待复测。** 复测可在补库读配方时首次翻页、保存单项目标，并重开网页核对保存值。

## 本轮改动

- **合并整组读取**：生产判断用一份完整新鲜快照，补料边界另读一次；换蜂、暂停/放行和等待之后重新采样。所有节点的配方、批量、消耗及完成证明仍检查。
- **批次配方索引**：每个工作器首次校验时读取登记文件并索引，之后内存匹配。新批次和恢复创建新工作器，重新加载；网页原有生产/样板互斥保持。生产期间不要用外部程序直接修改配方文件。
- **库存命中快速开工**：凝聚物已满足本批、子网无原液、没有未确认申请/搬运时，跳过供液口发现、原液稳定等待和纠缠启动。放行前再次核对库存、子网、接口、过滤和订单；释放共享供液锁，防止阻塞其他组。
- **蜂群检查去重**：初始检查合并整组暂停/纠缠器停机和共享蜂群确认，控制器沿用蜂群模块已验证的阶段需求。沿用现有蜂群时不搬盘；仍检查盘库、两只 IO 全槽、共享仓和旧日志，仍自动补充新放入的同类蜂群。饱和读数不能当作精确数量，未完成搬盘不重放。

保留独立供液子网、原地址、配置、登记配方、状态日志与恢复入口。V3 源码暂时仍位于 `reinstall_v2/files/`，游戏目录仍是 `/home/bec_v2/`，这次不迁移数据目录。仓库既有 V2 安装器和历史更新包保持原版；**试用本分支先使用本目录的 `update.lua`，再安装上面的 `update_cache_response.lua`，不要用旧安装器覆盖 V3**。本轮不含流水补液、下一单预取或自动均分订单。
