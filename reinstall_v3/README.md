# V3 第一阶段提速预览

分支 `codex/bec-v3-performance`，基于 V2 网页版 `a293a34`。重点缩短配方读取、换蜂检查和库存充足订单的开工等待。已通过 Lua 5.2 模拟，尚未 Minecraft 实机验收。

## 本轮改动

- **合并整组读取**：生产判断用一份完整新鲜快照，补料边界另读一次；换蜂、暂停/放行和等待之后重新采样。所有节点的配方、批量、消耗及完成证明仍检查。
- **批次配方索引**：每个工作器首次校验时读取登记文件并索引，之后内存匹配。新批次和恢复创建新工作器，重新加载；网页原有生产/样板互斥保持。生产期间不要用外部程序直接修改配方文件。
- **库存命中快速开工**：凝聚物已满足本批、子网无原液、没有未确认申请/搬运时，跳过供液口发现、原液稳定等待和纠缠启动。放行前再次核对库存、子网、接口、过滤和订单；释放共享供液锁，防止阻塞其他组。
- **蜂群检查去重**：初始检查合并整组暂停/纠缠器停机和共享蜂群确认，控制器沿用蜂群模块已验证的阶段需求。沿用现有蜂群时不搬盘；仍检查盘库、两只 IO 全槽、共享仓和旧日志，仍自动补充新放入的同类蜂群。饱和读数不能当作精确数量，未完成搬盘不重放。

保留独立供液子网、原地址、网页、配置、登记配方、状态日志与恢复入口。V3 源码暂时仍位于 `reinstall_v2/files/`，游戏目录仍是 `/home/bec_v2/`，这次不迁移数据目录。仓库既有 V2 安装器和历史更新包保持原版；**试用本分支请使用本目录的 `update.lua`，不要用旧安装器覆盖 V3**。本轮不含流水补液、下一单预取或自动均分订单。

## 已有 V2 网页版升级

更新器识别 `a293a34`、`07522a8` 对应的三个目标模块，并核对配套 engine/config。其他本地修改或缺失模块会明确拒绝，不覆盖。无需更换 OCHD 客户端。

1. 在 OC 按 **Q**，正常退出网页运行程序并暂停机器。若在 `lua>` 解释器，先 Ctrl+D 返回 OpenOS。
2. 下载并运行约 78 KiB 的三文件更新包：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/codex/bec-v3-performance/reinstall_v3/update.lua /home/bec_v3_update.lua
lua /home/bec_v3_update.lua
lua /home/bec_v2/main.lua web
```

更新器写临时文件、flush、回读后备份替换，任一替换失败回滚三个程序。检查更新空间并保留至少 512 KiB，支持没有 collectgarbage 的 OpenOS；临时安装包无法删除不阻止更新。不控制机器，不删除配方、配置或任何运行日志。

旧程序备份为各目标文件的 `.before-v3-performance-N`，三文件必须成套恢复，不能只恢复控制器。保留升级后形成的运行日志，不能通过删日志回退现场。若已有未确认搬运/申请，重新打开后仍由原恢复核对决定能否运行。

## 模拟结果及边界

对比对象是升级前 V2 `a293a34`，不是更早的慢版本。

| 场景 | V2 | V3 |
| --- | ---: | ---: |
| 16 节点、库存充足，从接单到收尾的节点读取次数 | 7,323 | 2,710 |
| 两个不同登记配方、两个批次，配方文件读取次数 | 174 | 4 |
| 16 节点已装蜂群的沿用检查，组件调用次数 | 219 | 185 |
| 库存充足测试场景首次放行，模拟秒 | 6.5 | 0.5 |

这些时间来自组件调用耗时为零、调度每 0.1 秒推进的模拟；不能当作实机开工时间或整体提速倍数。最后一行主要反映移除固定等待。实际受 OC 回调、磁盘、TPS、真实换盘以及配方耗时影响。[库存命中原始计数](evidence/stock-hit.json)。

复现：Python 3.12 + `lupa`（Lua 5.2），运行 `python reinstall_v3/run_tests.py`。脚本重建 V3 更新器，然后执行 129 项针对性测试及 20 个原核心场景。覆盖多节点、阶段换蜂、完成瞬间、恢复、不明回执不重放、缓存让位、库存/接口/配方突变、共享锁，以及六个替换位置失败回滚。历史 V2 安装包测试不在本轮范围，历史包内容没有重建。

实机先使用一个便宜配方，比较库存充足且同蜂群、需要换蜂、需要补液三种情况。关注“蜂群检查/换盘完成”耗时、是否出现“无需搬液和纠缠”、从接单到第一件产物的时间。新增的快速路径仍须真实游戏验证。
