# 网页缓存管理

顶部第三个页签「缓存管理」，位于「结构 / 绑定」「运行流程」旁。缓存页的目标已连接实际补库，不再使用「公共设置」里的库存参考值作为编辑入口。

## 使用

1. 用「样板处理」登记配方，应用机器绑定。
2. 打开「缓存管理」，设置默认库存目标（mB），点击「保存默认值」。初次使用沿用原配置的正整数参考目标，缺失或无效时为144000。
3. 每种流体可设置单项目标：留空继承默认值，0停止补充。每行点击「保存」。库存、实际目标与中文名称同时显示；超过8种时翻页。
4. 点击「启用自动补库」，并启动顶部自动化。空闲时按目标补差额；切回其他页签不会停止补库。运行中仍可修改缓存目标，本轮完成后采用新设置。
5. 「停止补库」不停止正常生产，已有申请/搬入部分先核对、转换收尾。顶部「暂停」同时请求生产和缓存暂停。Q退出会关闭纠缠器，保留操作记录；尚未确认的申请/搬运禁止重放。

只补已登记配方涉及的类型。普通流体按144mB、对应特殊流体按1000mB整批向上取整，最终库存可能略超目标。不会为了下调目标而清掉已有库存。

## 与V1的关系

`files/runtime/cache.lua`直接适配`reinstall/files/bec_cache.lua`，保留V1统一目标、单项覆盖、0停补、已存凝聚物抵扣、最低库存选择、整批取整、CPU繁忙等待、单次申请记录、持续收料、纠缠转换和订单让位协议。V2改动限于路径、后台让位回调和替代单节点生产检查的调度器保护。

新增`lib/cache.lua`将V1工作器映射到当前组地址/方向/已绑定高速口及全部纠缠器，持有V2同一组和主网供液锁。整组保持立即暂停，空闲节点开放下一单识别；一旦出现物理订单或登记产物的AE队列，停止追加申请，核对已提交申请并转换已搬原液后交回生产。其他组等待共享供液口。存在未结束生产记录的组不启动缓存。

设置独立保存在`/home/bec_v2/cache.config`，逐组操作记录为`state/group-N/cache.journal`。所有持久写入使用非美化序列化、flush与读回验证，旧设置有`.previous`。未确认缓存操作会阻止重新开始生产/补库，不通过删日志自动恢复。沿用V1限制历史归档占用的做法，只清理已完全确认的旧缓存归档，保留最近归档；当前、未完成、未知格式记录不清理。

## 安装更新

按Q退出旧服务，在OpenOS shell执行：

```sh
wget -f https://raw.githubusercontent.com/Alivn-chao/gtnh-bec-automation/bec-v2-cache-manager-2026-10-17/reinstall_v2/update_cache.lua /home/bec_cache_update.lua
lua /home/bec_cache_update.lua
lua /home/bec_v2/main.lua web
```

更新器只安装5个程序/页面文件，含2个新增缓存模块；已有文件精确版本校验、备份回读和失败回滚。绑定、配方、草稿、缓存设置、任何当前/历史日志均保留。为节省4MB硬盘空间，从上面指定路径运行时，会验证并移除已经载入内存的本次临时下载包；程序备份保留。无需更换客户端。其他包含新网页的更新器同步包含缓存后端；HTML单文件更新会拒绝缺少后端的旧版本。
