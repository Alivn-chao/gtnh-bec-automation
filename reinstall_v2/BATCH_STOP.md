# V2 批次接单控制（preview 3）

同步 V1 的批次启停：当前配方接单后，整组传送节点关闭工作许可，当前配方仍按红石暂停/放行运行。组内先完成的节点不接下一单；整组收尾并保存 stopped 后，在立即暂停信号下重新允许空闲节点接单。韦门过滤及三轮回读保持原逻辑。

节点地址必须同时提供 setWorkAllowed / isWorkAllowed。缺少接口时拒绝运行，需要检查适配器接线和节点组件绑定。没有按名字猜测或切换到其他机器地址。

暂停、故障和退出会关闭节点接单。启停写入独立的 state/node-N/batch-stop.dat（pending/confirmed，flush、回读和 previous 备份）；启停回读失败不能放行。未完成 cohort 或未核对生产日志不会自动重开接单。更改配置、未确认搬盘和生产记录仍按原规则人工核对，不重复执行。

已有 V2：先在游戏 Q 退出，保持节点暂停、纠缠器停止、蜂群 IO 无未完成动作；复制 update_reads.lua 后运行 `lua /home/update_reads.lua`。更新脚本只读检查硬件，备份并替换五个程序文件，失败回滚，不启动自动化。仅接受已知基准及读取优化 preview 版本，拒绝覆盖未知本地改动。

空硬盘：使用 dist/bec-v2-clean-install.zip 内的 install.lua，依 README 安装和绑定。

验证：Lua 5.2 下 96 项 unittest 及原有 20 项 V2 场景通过，含 16 节点全部关接单后才放行、先完成节点不提前接单、启停回读失败阻止放行、旧组不重开、监控只读、退出停机。硬件模型现已尊重节点工作许可，1ms 假设下快速连投可完成两个不同配方。未经 Minecraft 实机验证，模拟秒数不作为实际耗时承诺。
