# 阶段切换提速 · preview 2

针对两个实际反馈：出现需要换蜂后迟迟不搬盘，以及下一配方的韦门确认慢。本轮只优化 V2 阶段切换路径，不改机器自身配方速度，不改变蜂群选择优先级。

## 已改内容

- 蜂群硬盘箱固定只管理物理槽 1–10，沿用用户原先指定的范围。避免在 getAllStacks 不可用/索引不兼容时逐槽扫描 243 格；也不再批量导出整个大箱子。11 格以后不选盘、不搬盘、不作为空盘来源。需要的 10 类蜂群及可用空盘应安排在前10格；不是扫描前10个非空槽。
- 每次换蜂开始、结束仍全扫两只 ME IO 的全部12槽，拒绝其他槽位已有盘。单盘由输入1进入时，等待过程只读输入1/输出7；输出7在预检时已空，正常单盘操作会落入该格。输出不落7会超时保留现场，不会猜测或重放。实际移动前后仍重新确认盘、源/目的槽和数量。
- 同一轮准备中若已完成蜂群检查，后续进入准备分支不再立即重复执行整套 ensure；下一轮或运行中出现新需求时仍重新检查。取消、暂停和蜂群不足时的守卫不变。
- 韦门写过滤前进行完整组快照验证。随后三轮过滤、容量、开机和运行状态回读全部保留，每轮重新读取所有参与节点的状态和暂停输出，不再为了这一步重复读取需求、消耗、并行和等级。三轮结束后仍完整执行 unchanged/current 验证，通过后才允许供液、启动纠缠器或放行节点。
- 新增“检查蜂群 / 准备换盘”“开始首次搬盘 / 检查准备 X 秒”“蜂群检查/换盘完成 X 秒”“韦门确认 X 秒”提示。计时覆盖程序进入对应阶段后的实际耗时，不能当作从机器首次发出需求那一刻开始的服务端事件时间。

## 模拟对照

基线 549df6e；完整 Lua 5.2 核心。数字是组件调用数，不是现实秒数。

| 场景 | 原版 | 本版 |
| --- | ---: | ---: |
| 243格箱、批量接口不可用，首次搬盘前槽位读取 | 269 | 36 |
| 同场景首次搬盘前箱子读取（含移动前再确认） | 244 | 11 |
| 同场景完成装入的总槽位读取 | 305 | 67 |
| 16节点韦门确认阶段全部组件调用 | 351 | 207 |
| 上述韦门阶段节点getter调用 | 320 | 128 |
| 韦门过滤确认轮数 | 3 | 3 |

原版在批量接口完全可用且元数据齐全时不会逐个读取243格，该情况下不能套用第一行的降幅。具体耗时还受设备数、OC调用预算、磁盘写入、AE传输、服务器TPS及界面刷新影响。

## 安装预览更新

update_reads.lua 现在内嵌4个程序：bridge、engine、controller、nanites_cell。兼容原始549df6e、上一版读取优化preview1和本版；对其他本地修改拒绝覆盖。此前preview1的两个变化也包含在本版中。

1. 原UI按Q退出，全部节点暂停，所有纠缠器停止活动，保持约束场开启。
2. 如蜂群IO有未完成记录或端口留盘，先按原流程核对恢复；不能通过安装更新清除现场。更新器会拒绝未完成蜂群IO、非空端口或非零蜂群IO红石。
3. 将 update_reads.lua 复制到游戏电脑 `/home/bec_v2_update_reads.lua`，执行 `lua /home/bec_v2_update_reads.lua`。
4. 所有程序先暂存、语法检查、flush、逐字回读，再逐个备份和替换。失败恢复旧程序；备份后缀 `.before-read-opt-N`。不改配置、配方和journal，不启停机器、不搬盘。不要在仍运行的后台控制器旁执行。

配置和日志格式未改，不会重放未确认搬运。前10格规则仅应用于ME-IO蜂群硬盘模式，旧双接口蜂群模块不在本次提速范围。

## 验证边界

87项unittest及20项完整V2行为场景通过。新增覆盖：前10格边界、忽略第11格非受管物品、全部12槽预检拒绝留盘、同轮只检查一次蜂群、三轮确认保留、过滤/配方/暂停信号在确认中改变时禁止供液和放行、更新器兼容preview1及拒绝未知代码/未完成换蜂/留盘、失败回滚。已有整盘身份、超30720实物、部分搬运/丢响应不重放等回归均通过。

本版尚未在用户游戏安装和验收；不要把调用次数减少等同于固定秒数提速。先用同一配方/并行/盘与库存条件比较日志中检查准备与韦门确认耗时。
