# 实际配方速度诊断

只读单次诊断，不安装优化、不修改设置、不写日志。基于 Beta3 对应 GT5 5.09.54.133 固定提交 74150cf3b624e504fd72746606317a3f5b423667 的 MTEBECIONode.incrementProgressTime/getProcessingSpeed 与 BECFactoryNetwork.getSlowdowns。

将 probe_speed.lua 复制到 OC 的 /home/bec_probe_speed.lua，然后在 V2 电脑的 OpenOS 命令行执行 `lua /home/bec_probe_speed.lua`。需已有 /home/bec_v2 配置。只读取 7 个已知 getter/节点；不会主动暂停、恢复或改变任何机器。建议先用原 UI 的 Q 退出避免与生产界面争抢组件调用，诊断会注明暂停时估算不等于实际正在生产。

正常推进时：理论每服务器 tick 推进的配方 tick ≈ 可用蜂群读数 ÷ 并行数 ÷ 2^(提供等级−需求等级) ÷ max(污染减速数+1,手动减速系数)。缺电、观察阵列离线、暂停、等级不足、阶段边界、污染过多停机等会额外阻断推进，TPS 会影响现实秒数，不能据此精确承诺整单耗时。

程序显示蜂群数量、需求/提供等级、并行、污染数和手动减速，缺失读数不猜成0。getState/需求/消耗等均为顺序调用，非服务端原子快照。

关键优化候选：
1. 比较候选蜂群的有效数量 n/2^等级差，而不是只选最低合格等级或盲目最高等级。现有整盘模块优先最低合格等级；数量悬殊时未必最快。换盘耗时、读数封顶及当前持有蜂群还需纳入比较，不能按箱内数量直接当节点可用读数。本轮尚未改变选蜂或自动搬盘。
2. 过滤阻断可达的无关凝聚物，减少 getSlowdowns；污染超过3会触发源码中的clogged停机。不得为提速清空约束场，且输入仓每tick覆盖过滤的行为仍需核对。
3. 手动减速系数大于1时查明是否为此前防止超快配方丢需求而设定，后续只在停稳并确认供液守卫后调整，不能在运行中盲目设置。
4. 单批并行越大，其他条件相同时进度越慢，但一次产量也更多。多节点吞吐和单批延迟是两个目标，不能直接把降并行称为提高总产量。
5. 自动化层面提前规划下一阶段蜂群，精简全库存扫描和原液稳定固定等待；仍需保留完成证据与不能重放搬运的守卫。

本脚本6项Lua5.2模拟通过：同级、高一级减半、污染与手动系数取最大值、低等级阻断、方法flag=false可用与缺读数、空闲/暂停说明。未游戏验证。
