# Beta 3 空闲节点末批消耗恢复

节点 `clearCurrentRecipe()` 清空 required/parallel/state，但保留 consumed。旧恢复代码把“旧配方不等于当前空需求且 consumed 非零”误报为下一配方已消耗。此补丁只在 **idle、required=nil、parallel=0** 时将 consumed 作为末批单独抵扣；有活跃新配方时仍按原规则核对。

每种原料预算 = 原场库存 + 原子网原液 + 已确认搬入量。减去当前场库存、子网余液以及末批 consumed，加上流水初始 consumed 后，必须得到同一个非负整数配方份数。未知消耗类型、超过原记录需求、数量不守恒、未确认搬液或 AE 申请仍拒绝恢复。

## 安装与恢复

先 Q 退出 UI、等纠缠装置停稳。先安装 `fixes/batch_stop/patch_v1.lua`，再安装本目录 `patch_v1.lua`，然后 `lua /home/bec_ui.lua resume`。安装器要求逐批关机标记存在，以免恢复后继续自动跨批；原位更换恢复段，保留换蜂、逐批关机、过滤和 UI。安装不改日志，控制器自动备份 `.before-idle-recovery-N`，写入 flush/回读、替换失败还原、重复安装不写。

恢复核算通过后，另存 `/home/bec_auto.journal.idle-recovery-N`，包含原日志全文、末批消耗、原记录需求、库存、此前完整消耗份数及相对原记录缺口。原流水随后由原恢复程序原样归档 `.before-resume-N`。末批保留消耗不计为已交付输出。由于旧日志未必记录最后一次并行变化，`missingAgainstRecorded` 明确是相对原日志需求的缺口；不从该差额猜测最后一批是否成功。
