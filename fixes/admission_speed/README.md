# 固定批次的并行配置与配方检测提速

2026-10-28 用户完成512份原始屏蔽层后，通过MCP读取同一网页工作器日志：进料准备
2.60秒、搬盘与原料匹配0.75秒；生产工作器detect阶段27.0秒，三项重叠准备7.20秒。
旧日志没有独立的并行配置耗时，不能把整个detect时间算作并行计算时间。

原料盘已经匹配唯一登记配方，新工作器直接使用该批保存的配方名、凝聚物单份需求
和产物，不再扫描全部登记目录。实时节点需求仍须与此登记一致；不一致直接停止，
不回退猜测其他配方。启动诊断和等待只读代表节点，进入准备前仍完整检查整组状态、
暂停输出、需求和消耗。冻结盘份数不会增长，因此省去等待任务清单稳定的额外轮询。

仅固定批次代表模式复用正式组件地址，不再三次列举网络；同一工作器按组件缓存
方法列表，各必需方法仍逐项验证，false仍表示方法存在。真实状态不使用跨批次缓存。

并行分配仍读取16台原设置、按边界顺序差量设置并逐台回读。整组先写一次pending
意图，全部确认后写一次完成，16台的整份记录写入从32次变成2次；并行还原同样合并。
部分成功、回执未知或中途暂停保留整组pending，不自动重放或接单。逐台原料接单、
实际份数/配方核对、盘内余料检查、回空盘，以及最终消费完成证明均保留。

新增日志区分“并行分配与回读”“逐台接单核对与回盘”“启动接口与旧记录核对”，
原料盘journal.timings及生产journal.startupSeconds也保存耗时，便于下一批实测。

279项回归及20核心场景通过。相同16台/36份登记模拟：首次准备前组件调用533→327，
方法列表读取52→38，组件列举3→0，生产工作器配方文件读取36→0；不是实机耗时比例。
9项新增覆盖唯一冻结配方和产物、需求不符、非冻结回退、整组合并保存、暂停、
未知设置/还原结果不重试，以及完整工作器路径。普通顺序模式保留原检查路径。
