# V1 快速换蜂与接单

用户 2026-10-13 截图显示 60/64 并行、需求 T4、蜂群为0、正在回收T2存储盘，要求加快切换和其他过程。

## 改动

- 阶段换蜂由“一次 needsSwitch 扫描、一次 ensure 再扫描”改为 `ensure(stage=true)` 单次决策；每个实际搬盘仍重读源/目标并核对数量。
- 已有需求相同类型、等级且至少64个蜂群时，阶段协调器无需扫描硬盘盒。兼容库存使用时每0.5秒复查是否有对应类型，原间隔2秒；需求变化仍立即检查。
- ME IO 等待与空槽检查使用 getAllStacks 批量快照，支持缺元数据时逐槽补读、接口不可用或索引异常时回退。IO轮询0.1→0.05秒，30秒超时不变。
- 被动 guard 一次读完整蜂群需求，避免类型和等级重复读取。
- 没有实际换蜂动作时不创建生产换蜂记录或打印换蜂事件；真正动作开始前才持久化控制器记录。
- 首次验证节点启停组件的身份后，状态已经相同时避免重复读取状态/并行/需求；实际写之前仍比较身份，写后回读。逐批关机不变。
- 接单稳定检查0.25→0.05秒，最大采样数20→100，保留原名义5秒等待范围。原顺序备料路径20次原液稳定检查从5秒改为1秒，每次仍读取核对。
- 完成换蜂的事件附带实际耗时，便于游戏里对比。

不缓存盘数量跨操作；搬盘未确认不重试。ME IO 的真实搬运速率、服务器TPS和OC调用预算仍会影响实际耗时。

## 安装

**先等本次换蜂完成，再按 Q 退出 UI**；等纠缠装置停稳后运行 `patch_v1.lua`。一个安装器内置蜂群模块，同时原位修补 `/home/bec_auto.lua` 和替换 `/home/bec_nanites.lua`。要求阶段被动换蜂V2与逐批关机已安装，保留空闲恢复补丁及其他控制器逻辑。

安装前核对蜂群IO日志done及端口空闲，不改变日志和盘。两文件先完成临时写入、flush、回读和语法检查，再备份替换；第二文件失败会同时回滚第一个。成功备份为 `.before-fast-cycle-N`，重复安装不写。成功后 `lua /home/bec_ui.lua resume`。
