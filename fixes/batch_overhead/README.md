# 接单参数、归档清理与生产供液路线

本轮实现用户优先选择的三项优化，保持原料盘收集10秒、先搬盘后计数和接单顺序。

## 并行参数差量写

只写与已确认值不同的最小/最大并行，按合法范围排序：降低上限前先降低过高的
最小值，提高最小值前先提高不足的上限。写前意图、写后实际回读保留；不明确的
写入结果不重放。收尾只恢复参与节点，不再改动未参与节点。

模拟设置及收尾的参数写入：3次配方57→6，16次各1份96→32，1000次96→64；
所有无变化的setter调用被移除。这些数字不包含仍保留的读取和其他控制操作。

## 按需清理归档

保留每10秒轻量空间检查，启动空闲时和批次完成后请求归档清理；有生产、接单
或缓存资源占用时推迟常规清理。空间不足立即尝试清理已确认旧归档，重复紧急
清理间隔至少60秒；若仍不足或容量不可读，仍暂停。正常清理不推迟首次低空间
事件的处理。原有归档保留数量、未完成/未知记录保护不变。

## 生产与后台补库复用路线

新增 `lib/fluid_discovery.lua`，读取相同 `state/group-N/cache-discovery.dat`。
核对正式绑定全文、配置内地址、方向、记录数量，原液别名限于该凝聚物的已知
候选。生产只探测本次确实需要补入的口：来源/接收方向、容量和流体名称；位置
或流体不匹配才重新扫描，随后保存兼容的路线记录，下一批或重启可复用。

已知来源暂空可保留路线并申请正确原液，但真实搬运前仍要求流体名称匹配、接收
接口为空、回执和子网增量吻合。缺少该辅助模块的历史三文件更新保持内存发现
方式，不会因可选文件缺失使旧安装失效；历史更新器仍不是完整批次模式安装器。

10路模拟中，首次完整发现90次读取；已知且仅需1路时探测5次。真实生产控制器
连续两种配方只发现一次，第二批复用保存路线；已知空来源下只申请一次并完整
搬入正确流体。不同绑定、未绑定地址、方向变化、错误原液与恶意别名均有回归。

## 验证与试用

`python reinstall_v3/run_tests.py`：220项回归及20个核心场景通过，其中新增18项
参数/清理/生产路线测试，并将已有2项存储保留测试纳入统一入口。数字均为模拟
调用量，不能视为Minecraft秒数。

实机空闲窗口通过MCP安装新模块及cell_feed、engine、bridge、controller，保留
备份并逐字回读，配置/接线/原料盘及既有蜂群模块不改。网页重开后保持暂停，
点右上角启动即可。建议先测小单，再连续两批，比较投料到开工及需要补液时的
备料等待；库存已够的订单仍走原来的库存命中路径。
