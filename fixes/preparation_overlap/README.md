# 换蜂、韦门、供液与转换重叠

固定原料盘批次且启用代表检查时，同一个生产工作器交错推进换蜂、韦门确认、原液
备料。它们共享原来的组锁和供液锁；没有另开生产进程或后台缓存工作器争抢原料。
三项都完成后才放行传送节点。其他模式或缺少新增模块仍走原顺序流程。

韦门仍完成三轮确认。确认后，高速口已核对到账的本批原液可以立即进入纠缠转换，
不必等待换蜂结束，也不必等待后续原液申请完成。换蜂 IO 在这个受控准备区间内
允许本工作器的纠缠器工作；普通换蜂、未知工作器和正常生产阶段的旧守卫保持。
只有这一轮受控准备允许边搬边转；结束后回到原来的批次管理，不把纠缠器常开。

供液保存起始凝聚物库存和已确认原液总量，用“凝聚物前读→子网→凝聚物后读”的
区间核对转换过程，避免把已转换的原液再计一次。每次原液搬运的意图、回执和库存
核对保留；未知回执不重试。普通接口回退仍先收齐再转换。任一分支失败或用户暂停，
已启动分支先完成自己的退出清理，再关闭蜂群 IO 和纠缠器；原日志与未确认申请保留。

原料每次搬入已经核对实际增量，所以受控准备去掉了随后固定20轮全组稳定扫描，
在转换与放行边界重新核对。失败恢复会先停机核对保存的转换总账，抵扣真实原液/
凝聚物；只有所有旧AE申请、搬运都明确完成且无pending时才接受，已知记录不重放。

日志新增“并行准备完成”及换蜂/门/供液转换从共同起点到完成的耗时。这些时间有
重叠，不能相加。生产日志中的`preparation`保留同样数据，便于下一轮MCP比较。

本轮读取实机14个工作器保留的最近批次：初次换蜂约17–24秒、门约3–5秒；缺库的
6批备料19–72秒，转换约32–35秒。单个工作器的蜂群总耗时包含后续多次换蜂，不能
当作首次换蜂时间。部分历史时间线只保留最后12项，分析没有虚构更早的阶段细节。

270项回归与20核心场景通过。新增10项包含真实Lua蜂群/门/生产控制器的协作、
边收第二种原液边转换第一种、CPU申请一次、未知回执、错误门、暂停清理、已确认
转换恢复不重搬、库存命中不启动纠缠器，以及相同模型首次开工26.65→13.40秒。
模型明确假设IO8秒、后续原液10秒到账、转换3秒；不等于真实游戏的提速比例。

需要`lib/preparation.lua`、`lib/bridge.lua`、`runtime/controller.lua`三个配套模块。
旧三文件V3更新器没有新增模块，不能作为本功能的完整安装器。实际实体蜂群模块、
缓存并行下单、配方、接线及配置不需要更改。当前机器通过MCP按版本条件备份安装，
实际生产耗时等待下一批正常订单验证；没有为测速下AE订单或搬蜂。
