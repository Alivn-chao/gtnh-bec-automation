# V1 大订单自动分批

旧控制器把 AE CPU 的整单剩余量全部换算成凝聚物，再检查每种流体是否超过 2,147,483,647 mB。因此一个正常的大订单会报“整批需求过大”，运行中的库存也会不断与整单需求比较，造成重复暂停。

新逻辑保留 AE 整单，只准备能安全供液的一段。按所有流体共同限制计算本轮配方份数，并向下对齐 144/1000 mB 转换单位，避免原液向上取整后超过单次接口范围。库存足够就连续生产；接近下一轮所需量时暂停备料，随后接着做，直到订单完成。追加订单不会因为总量很大立刻再次暂停。

库存每次轮询检查；AE 队列通常每秒读取一次，只有触发补料时再读一遍确认，避免队列缓存变化导致多余暂停。不会取消 AE 订单、清空库存、修改缓存目标、删日志或重复未确认搬料。新窗口记录按物料总量核对转换恢复，旧日志的恢复限制保留。

## 安装

适用于当前 V1 `/home/bec_auto.lua`；支持原版、蜂群/韦门版本和并行收液纠缠补丁。先正常按 Q 退出界面，使节点暂停15、纠缠器关闭并停稳。下载本目录 `patch_v1.lua` 到 `/home/bec_patch_window.lua`，然后运行：

```sh
lua /home/bec_patch_window.lua
lua /home/bec_ui.lua resume
```

安装只改备料窗口、库存补料触发和相关显示，保留已有蜂群、过滤、流水备料和其他修正。写入前检查唯一定位和 Lua 语法；生成 `.before-window-N` 备份，显式 flush/回读，替换失败还原。重复安装不再写文件。若定位不匹配就停止，原控制器不改。

整体订单可以超过接口上限；如果**当前已经进入机器的一轮实际并行需求本身**就超过单次供液范围，仍需降低机器最大并行。程序不擅自变更已进入机器的这一轮，也不假装物料够用。

## 验证

`test_window.py` 使用 Lua 5.2 验证百万/十亿份队列窗口、追加大订单不暂停、低库存接续、144/1000单位、并行及消耗抵扣、安装/回滚/备份/日志不改。完整控制器模拟十亿份队列连续运行后 Q 停止，以及缩小测试上限后的一个订单跨多轮备料完成；转换恢复窗口计数变化时按物料核对且不重复搬运。可用本地历史 V1 文件时还测试旧蜂群版和流水补丁共存。这些是模拟测试，当前游戏补丁仍待用户安装验证。
