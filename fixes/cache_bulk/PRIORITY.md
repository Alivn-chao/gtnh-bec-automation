# 配方优先于后台缓存

生产控制器本来在节点有配方时直接处理生产，但后台缓存一次补整种到144000mB，并允许已暂停节点状态继续补缓存，导致新配方可能等待整个缓存轮次。本补丁定位修改现有 `/home/bec_cache.lua`，保留原流水生产、蜂群、UI及日志，唯一备份/语法检查/flush回读/替换失败还原。

安装：正常Q退出后下载 `patch_priority.lua` 到 `/home/bec_patch_priority.lua`，执行 `lua /home/bec_patch_priority.lua`，再 `lua /home/bec_ui.lua run`。

- 后台新批次检查节点状态和主网busyCPU的activeItems/pendingItems，识别全部登记配方的产物。有配方任务则不启动补库；无法读取busyCPU任务时保守交回生产。队列检查最多每秒一次，节点状态每次直接读。
- 空闲时后台每段最多16000mB，按转换整批向下取整（144批量为15984），统一最终库存目标保持配置值。独立高速口批量搬运保持不变。手动run-stock仍一次补至指定完整目标。
- 补库收液期间发现配方后，不再搬入更多缓存原液或提交/重试缓存申请。无正在AE合成的申请时立刻缩小本轮缓存目标到已有凝聚物+已确认搬入原液，转换完这些原液、关闭GEN后交回生产。未收取的原液保留主网供生产使用。
- 已提交AE申请需要先确认done，不能丢弃结果或将它直接标成done；这段确认仍可能等待上游合成。申请不明/取消、部分搬运及非守恒原液仍拒绝恢复，不自动重下单。
- 旧incomplete缓存在已有配方时只处理已持有原液，不继续补原目标；完成后incomplete=false，随后生产控制器继续按当前配方真实需求备料。不会取消主网成品任务或重启机器故障配方。

`build_priority.py`从现有高速缓存模块和定位规则生成 `bec_cache_priority.lua` 与安装器；运行时不依赖Python。`test_priority.py`用Lua5.2验证定位安装/回滚/日志保留/重复安装、节点已有配方、仅AE队列有登记产物、队列不可读、小段补库、中途新配方且AE申请在途、旧incomplete安全交回、无关原液/未完成请求拒绝及手动完整缓存。测试为模拟，实机响应和转换耗时待验证。
