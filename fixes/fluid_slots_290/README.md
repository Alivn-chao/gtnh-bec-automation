# 供液接口槽位编号兼容

实际 OC AE2FC 方块流体接口使用1–6号配置槽。原控制器、缓存及全量检查使用内部
0–5号编号，在检查0号槽时会触发 index out of bounds，本批已接单任务进入保护。

兼容处理集中在 lib/config.lua 的组件包装器，仅针对
getFluidInterfaceConfiguration / setFluidInterfaceConfiguration 的显式配置槽号：

- 首次使用某个接口时只读识别编号。0号读取合法则保持旧协议；仅在明确槽位越界、
  且6号读取合法时，识别为1–6协议，把内部0–5映射为物理1–6。
- 每个配置实例按地址记忆结果，多个包装器共享；正常运行不反复探测。旧协议首次
  读取0号时复用识别结果，保持原调用次数，不额外改变旧流程中的时序。
- 配置和清除使用同一映射，写操作只提交一次。异常、false或未知写回执不会重发。
  非槽位错误直接保留，不把网络故障当成编号差异。
- 只改变供液配置槽号；组件地址、转运器方向、红石面、物品盘位均不变。
  第6个物理槽仍参与完整检查，存在配置时仍拒绝启动。
- cache_zero_recover.lua也使用相同包装器，避免手动核对工具再次读取非法0号槽。

现场只读探测确认：0号、7号及以上越界，1–6号全部合法且配置为空；两侧常规流体
接口均6槽。实际安装后的包装器已重新检查全部6个配置槽。依据当前 JAR 中
li.cil.oc.integration.ae2fc.DriverBlockFluidInterface$Environment 的实现核对：
显式参数会减1，读取默认槽号为1，没有用最新开发分支推断。
