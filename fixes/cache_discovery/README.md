# 固定信息与实时信息分离

- 配方流体目录、每配方最大需求、产物索引：由现有目录读取一次共同生成；不再在每轮后台补库中重读。样板处理结束/失败、手动刷新会使目录失效。重启程序重新读取登记配方一次，避免复用外部已修改文件。
- 高速供液口位置与原液别名：按设备组记忆，且保存到 `state/group-N/cache-discovery.dat`。下次重启在正式配置文本完全相同时复用；不读取旧绑定下的路线。缓存文件损坏或包含未绑定地址则放弃缓存重新发现。
- 使用前仅探测本轮所需端口的方向、容量、流体类型；失败才全扫描。空的已知源口保留映射，真正搬液前仍必须读取正确流体名称并核对接收口为空。不会凭缓存搬运。
- 原液别名只能是该凝聚物的已知候选，不能把持久化别名变成任意其它流体。需要AE下单时仍实时获取合成对象，沿用原请求日志；不会复用旧合成对象或重放未确认任务。
- 库存、节点/纠缠器状态、实际搬运、请求完成状态继续实时检查。

同时保留并同步实际OC已有的保护：缓存占用供液时关闭节点下一批接单许可；工作器启动前再查一次是否已有节点接单，若有则让回生产，不创建缓存操作。

`patch.py` 和 `persist_host.lua.inc` 是受检源码转换，实际部署前需读取实际文件并确认基线，不能盲目覆盖已有其它版本。补丁保留了实机的关闭接单保护。运行 `python fixes/cache_discovery/test_cache_discovery.py` 或 `python reinstall_v3/run_tests.py`。

测试覆盖多轮复用、新样板目录失效、端口换方向、已知源口暂空、手动重扫、重启复用、绑定/地址失效、错误别名。模拟三轮补库中没有新增配方文件读取或全扫描；这不是实机耗时测量。
