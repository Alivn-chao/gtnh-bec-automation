# V1 生产备料流水处理

对实际上传的V1控制器原位安装，不替换UI/蜂群模块/缓存模块，不修改订单或日志，不执行机器操作。唯一 `.before-pipeline-N` 备份，语法检查、flush/回读、替换失败还原。兼容此前进程重置、跳配方和蜂群需求判断补丁。

正常Q退出后下载 `patch_v1.lua` 到 `/home/bec_patch_pipeline.lua`，执行：

```sh
lua /home/bec_patch_pipeline.lua
lua /home/bec_ui.lua run
```

有可恢复的非正常停止日志时仍使用原来的 `resume`；安装不会删日志绕过恢复检查。

本轮生产目标所需原液都有可识别的独立高速缓存器/转运器口时：

- 逐个调用AE申请API，但不等上一单完成；每次重读空闲CPU，有空闲CPU即提交其他流体缺口。实际并行数受AE合成CPU及原液生产设备限制。
- 每轮查看各原液到账情况，按完整转换批量精确搬入子网。第一种到货后纠缠开始，之后收料/合成与纠缠重叠；不用等全部原液齐全。
- 累计记录原有凝聚物、原有原液、确认搬入量。纠缠中的原液不当作丢失，不按动态子网余额重复补液。读场再读子网，允许正在转换的数量暂时不在两者中；最终必须目标凝聚物齐备、子网空、纠缠当前工作结束、所有AE申请完成。
- 装配节点全程暂停，最后才放行。流水完成后省去原先原液稳定检查固定5秒等待；旧顺序路径保留原检查。
- 缺任一所需高速口时保留原顺序路径，避免擅自改变普通单槽接口的配置与缓存归网逻辑。后台空闲缓存仍由原缓存模块处理，不改其分段补库策略。

`pipeline`记录仅属于未完成生产轮次，保留pending意图、requests和每次transfer结果。部分/不明搬运、申请取消/状态不明、暂停订单变化、超额库存均停止且不重试。Q可能留下正在AE合成的请求，恢复仍拒绝未核对完成的请求。申请均已确认完成的流水暂停可以用resume：要求节点暂停、纠缠关闭且当前转换已结束，逐种验证凝聚物+子网原液等于原有库存+已确认搬入量，再归档旧日志并按实际库存抵扣继续。不自动将未完成申请改成done。

测试入口（Lua5.2/Lupa）：

```sh
python fixes/pipeline/test_pipeline.py /path/to/actual/bec_auto.lua
```
