# 缓存需求索引与空转优化

实机55份配方的首次索引读取/落盘约1.70秒；创建新读取器后复用约0.15秒，
55份正文读取次数为0。数据来自2026-10-26 OC MCP只读测量，不代表整轮补库耗时。

`lib/cache_catalogue.lua` 把每份已登记配方的凝聚物需求、产物标识和文件版本，保存到
`/home/bec_v2/state/cache-catalogue.dat`。重开时只比对文件大小/修改时间，新增或修改
的文件单独解析，移除的配方从索引中删除。运行中无需重复检查。样板处理完成后刷新
目录；只读预览保持已知目录，点击缓存的“刷新”可强制重建。外部直接修改配方文件
后也可点刷新，处理大小/修改时间没有变化的特殊情况。

这是一份派生数据：损坏、目录变化或无法复用时回退原配方库，不修改配方/生产/AE
日志。索引最多64KiB，仅当前文件及 `.previous` 一份备份；保存前给生产保留512KiB，
空间不足时只用内存索引，不阻止已知配方使用。没有依赖模块的旧部署仍走原内存扫描。

补库调度现在先看组锁与实际库存。生产占用/原料盘待处理时直接跳过该组；库存已满
时不再构造补库工作器、扫描16台状态及日志、反复写暂停/纠缠器开关。真正缺料后才
走原检查与供液事务；未确认AE/搬运结果仍保留，真实库存/收料/转换继续实时核对。
同一工作器启动与旧日志归档之间共用一次清理结果，消除紧接着的重复归档扫描。

模拟16台、20秒库存全满空转：组件调用552→4，节点调用384→0，启停写入72→0，
结果没有新的申请/搬运；这只是调用次数。新增9项测试覆盖重启零正文读取、单文件
更新/删除、强制刷新、坏索引、低空间、空转/生产让位、库存不可读和只读样板预览。
241项回归加20个核心场景通过。

本轮已通过MCP安装 `lib/cache_catalogue.lua`、`lib/cache.lua`、`lib/web_session.lua`，
旧文件带版本条件备份并逐字回读。生产控制器、实际兼容蜂群模块、配置和已有记录
没有替换。网页在原暂停状态重新打开，用户点“启动自动化”继续。
旧响应更新器只含原来的六个目标文件，完整持久索引功能还需要新增catalogue模块；
不要把旧响应更新包当作当前部署的完整安装器。
