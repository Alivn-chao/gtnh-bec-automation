# 等待合成 CPU 与手动补料

适用于已有生产并行 V3 和暂停原因 UI 的 `/home/bec_auto.lua`、`/home/bec_ui.lua`。原位修改下单函数与 UI 提示，保留最新被动换蜂、逐批控制、空闲恢复和快速换蜂代码；不替换蜂群模块。

- 全部 CPU 忙时等待，每轮继续收料、纠缠与核对当前生产。空闲后自动申请各自缺口。
- 已提交的合成任务继续核对，不因原先的 1800 秒申请时限报错退出。
- 只有 `isComputing()==false` 且 `hasFailed()==true` 才将申请记录为明确未提交的 `rejected`。按用户最新要求进入手动补料，关闭该笔缺口的自动申请，避免与手动下单重复。
- UI 红底白字显示流体原名与剩余 mB；多笔每 5 秒轮换。手动申请的原液进入主网后，自动搬入独立子网、纠缠、够料即生产。分批到账时数量随实际缺口更新。
- 空 CPU 列表、全部存储为零，或全部空闲且 AE 明确报告存储不足，显示“CPU 容量不足”。通用 `missing resources?` 只显示容量或原料待核对。
- 返回 nil、抛错、无法证明未启动的取消仍保留未确认记录，禁止自动重下。

OpenComputers 当前 [AE 接口源码](https://github.com/GTNewHorizons/OpenComputers/blob/master-MC1.7.10/src/main/scala/li/cil/oc/integration/appeng/NetworkControl.scala) 提供 CPU `storage`，但 `Craftable.request()` 不提供计划所需字节数；提交失败还可能统一返回 `missing resources?`。不能把原液 mB 当成 CPU 字节，不能仅从空闲 CPU 数量判定容量够不够。用户 Beta 3 可能不同，程序检查状态回调是否存在。

## 安装

先按 Q 正常退出 UI，等纠缠装置停稳，下载并运行本目录 `patch_v1.lua`，然后 `lua /home/bec_ui.lua resume`。安装器先检查两份源码入口和语法，临时文件 flush/回读，检查停机状态，再逐份备份替换；第二份失败会还原两份。重复安装不再次修改。旧配置、订单、日志不改。

**安装不修复旧 submitted 记录。** 用户截图的三笔请求只有提交意图，忙碌 CPU 的任务明细不可读，无法确认已启动、完成或拒绝。恢复仍会拒绝重复申请这些订单，需先在 ME 核对。新失败手动补料若按 Q 中断，恢复前必须收到记录中的完整缺口；未收齐不自动转回申请。
