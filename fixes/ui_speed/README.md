# V1 面板响应优化（UI_SPEED_V2）

对实际上传的 `bec_ui.lua` 定位修改，生成唯一 `.before-ui-speed-N` 备份，语法检查、flush/回读、替换失败还原。不修改生产控制器、订单、缓存/蜂群模块或日志，也不启停机器。退出当前UI后安装：

```sh
lua /home/bec_patch_ui.lua
lua /home/bec_ui.lua run
```

- 面板显示用组件数据缓存2秒，最大并行30秒；日志2秒、配置10秒、配方登记60秒。只影响展示，控制器继续直接读取真实组件。
- 自动重画间隔从1秒改为2秒；翻页立即绘制，复用近期数据。R明确清缓存并重新采样。
- 删除未使用的消耗记录展示查询。主循环先处理输入、再绘制；逐项采样之间非阻塞读取事件，Q优先停止，其他事件排队保留。初次绘图时收到Q则不启动控制器。
- 蜂群状态优先读取真实的新IO日志，done显示待命，不再把保留的旧接口filling记录当正在装入。
- 控制器组件调用完成后，每累计至少50毫秒主动交回UI调度；不增加机器暂停或固定等待。单个组件调用内部、纯计算、文件读取和组件代理方法仍可能阻塞，不能保证50毫秒内响应。
- 退出时写一份 `/home/bec_ui.perf`，记录展示组件查询、文件读取、绘图、控制器组件调用和每次协程执行的次数/总耗时/最大耗时，单位秒。各层时间有包含关系，不能直接相加。`controller.resume`不包含交回UI后的时间；不是整个生产周期用时。

安装兼容原版UI和此前的UI_SPEED_V1，可重复运行。启动后运行约30秒，正常Q退出，再执行：

```sh
cat /home/bec_ui.perf
```

记录仅包含最近这次UI运行，不扫描历史日志。用最大耗时判断长时间不刷新发生在展示查询/绘图还是控制器执行；控制器执行很长而组件调用很短时，还需定位控制器中的文件读取、代理调用或计算。这个补丁没有减少生产安全核对。

Lua5.2模拟实际上传UI验证唯一备份/重复安装/旧版升级一致、未改控制器和生产日志、连续翻页仅读取一次库存状态、false状态正确显示、IO done优先、采样中Q停止后不继续查询/不启动控制器、忙碌控制器交回调度后响应Q、多返回值含false/nil不丢失、退出恢复component.invoke并写耗时记录。没有实机帧率数据，不声称已经解决服务器TPS或终端自身输入延迟；此补丁针对生产面板的额外开销。
