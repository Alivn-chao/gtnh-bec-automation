# 暂停原因与继续

先安装 `patch_v1.lua` 的 UI 调度 V2，再安装 `patch_pause.lua`，均在正常 Q 停止后进行。
安装器只定位修改 `/home/bec_ui.lua`，先编译、临时文件 flush 回读、唯一备份。
不修改控制器、缓存模块、配置或 journal。

控制器打印“程序停止”或抛出异常时，面板保持打开，以红底白字显示首行原因，
省去 traceback 并移除开头源码路径。事件标题改为已暂停，避免把旧日志阶段当当前任务。
下方 T 重试/继续可鼠标点击或按 T。只有当前控制器已停且故障状态才允许重新启动；
存在生产 journal 则进入既有 `resume` 校验，没有记录才进入 `run`。
校验再次失败继续显示原因，绝不由 UI 标记申请 done、删除日志或重置搬料记录。
供电、阵列离线、蜂群等级不足显示对应等待提示，现有常驻服务自行检查，不另起服务。
Q 正常退出；缓存单项设置与调度 V2 保留。

这不是旧缓存未确认订单的恢复补丁：当前 stream-crafting/submitted 日志仍需实物核对，
不能由一个“继续”按钮跳过。界面也无法仅据 AE 申请返回值准确显示缺少的材料清单。

`test_pause.py <实际上传bec_ui.lua>` 在 Lua5.2 模拟运行实际面板，检查编译、重复安装、
红底白字、鼠标继续仅进入 resume 一次、异常再次失败仍保留面板、Q、journal不改。
实机仍待用户验证。
