# 固定配额同时接单

2026-10-31：原料盘冻结并匹配唯一配方后，先为所有参与节点设置并回读
`minParallel=maxParallel=本台配额`，确认立即暂停和空闲关闭接单，再连续开放
全部参与节点。OC 调用仍依次发出，但不等待前一台接单完成再开放下一台。
不同节点可以在不同游戏 tick 接单，慢节点不阻挡其他节点领取自己的配额。

全体接到任务后，用整组意图关闭后续接单并逐台回读，然后核对每台实际暂停状态、
真实并行及凝聚物需求。过渡态 crafting 继续等暂停，不重新开放节点；已经核对
通过的节点不反复查询需求。全部通过且生产盘为空才回盘、进入原有准备工作器。
10秒攒料、最大并行代表检查、换蜂/门/备料重叠、阶段追赶及最终消耗证明不变。

开放和关闭各使用一份整组 pending 意图及一份完成记录，代替原来逐台接单的多份
cell-feed/batch-stop 写盘。每台实际许可仍回读；不明回执保留整组意图，引擎暂停
全组，普通重启和旧 waiting-node 修复入口都拒绝自动重放。此版没有新增自动恢复
未完成并发接单的入口；应核对实际任务和余料，不能删除 journal 强行重跑。
已完整 ready 的检查点仍可使用原显式 ready 恢复逻辑。

默认仅对启用了 cellFeed 的新批次生效，原 waiting-node 记录沿用旧顺序修复路径。
需要退回顺序接单时，在完整收尾后将 `groups[N].cellFeed.concurrentAdmission=false`；
省略此字段为同时接单。不可在未完成批次中切换模式。其他非原料盘模式不受影响。

新增11项模拟回归，覆盖16台先配置再开放、异步/乱序接单、1/3台小批次、过渡态、
未知开放/关闭回执不重放、错误配额/配方/余料、暂停及引擎故障收尾。
相同16台模型，包含搬盘/配置在内的接单记录写入122→15次；这不是实机秒数。
完整296项回归和20项核心场景通过。

源文件为 `reinstall_v2/files/lib/cell_feed.lua` 和 `lib/config.lua`，游戏路径仍是
`/home/bec_v2`。旧V3三文件更新器不含 cell_feed，不能安装此功能。部署需要在
生产/feed/cache 均完整停止的窗口替换程序，保留配置、配方和当前运行记录。
