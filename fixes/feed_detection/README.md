# 缓存让位与进料识别前检测优化

用户明确保留10秒攒料，本轮不改变配置/等待窗口/接线。

- 接料准备合并为逐台确认关闭接单、确认idle和暂停信号，不再先全扫一次、关闭后又全扫一次。
  已暂停时不重复写15；真实改变后仍立即回读。关闭许可前若已接单，或关闭中发生接单竞态，
  均在移动原料盘前等待，不把旧idle读数作为放行依据。
- 驱动器的20个盘位用两份完整库存读取。实际OC `getAllStacks().getAll()` 返回0..9键、空位
  也是表，方法本身是可调用表。已实机只读确认10槽及每侧约0.15秒。不可用/不完整时回退
  原逐槽读取；搬盘前目标/来源、回执、搬后两槽仍新鲜检查。
- 接单期间盘已移离缓存槽，不再轮询不存在的来源盘；返回空盘后恢复轮询。确认过的固定
  配额和需求交给engine复用，只重读一个参考节点的身份，最终运行状态及消耗证明仍保留。
- 新料到达主动唤醒休眠缓存工作器，让位仍先核对已申请/搬入部分。已关闭纠缠器不重复写
  关闭指令；常规归档不挡住等待进料，容量检查与低空间紧急清理仍保留。
- 日志增加准备检查、搬盘与匹配分段耗时，不增加周期写盘。

模拟16台至首次配方匹配：c.invoke调用125→59，准备阶段无用暂停写16→0。
这不含固定10秒攒料，也不是Minecraft整体耗时测量。新增9项测试涵盖完整盘位/回退、
接单竞态、暂停回读失败、停止轮询、复用身份、唤醒缓存及暂停检查点。250回归+20核心通过。
