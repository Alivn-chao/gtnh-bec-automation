# 固定批次的换蜂检查复用

用户希望继续减少固定流程的检查。仅在已启用代表节点检查的固定原料盘批次中使用：

- 代表节点的配方需求和并行在本批首次使用时核对，随后复用；普通生产快照仍检查
  实际配方/并行，完整完成证明不变。
- 蜂群阶段需求在一次暂停期间复用。每次暂停/放行指令清除此缓存，下一阶段重新
  读取；运行中的需求查询保持新鲜，不沿用暂停期旧值。
- 实体总线和IO端口布局在本批首次确认，后续复用。实体蜂群槽的实际类型/展示量
  每次仍读，整盘数量仍来自实际盘内清单。
- 首次检查双IO全部24槽；随后本批仅检查程序管理的输入1/输出7。程序只操作这些
  槽，重启/恢复产生新工作器后重新全查，首次发现其他槽有盘仍停止。
- 首次和实际搬盘/启用IO前确认纠缠器停机；其间的只读等待复用确认结果。
  程序控制纠缠器或暂停输出变化时清除记录；取消标志与代表暂停状态一直检查。

复用数据只保留在本批工作器内，不写入磁盘作为下一次运行的证据。未知搬盘回执、
旧未完成记录、盘内类型/数量变化、阵列未识别仍保留记录并停止，不盲目重试。
变更绑定、手动调整设备或IO时，正常暂停并重新启动工作器，让首次检查重新执行。

`files/runtime/nanites_cell.lua` 是保留现有实体蜂群/阵列刷新修复的实机兼容版本；
`patch_runtime.py` 为针对此前版本的精确源码编辑，不能对未知版本直接覆盖。
桥接、代表和实体读取器在 `reinstall_v2/files/lib/`。旧三文件更新器不是本扩展
的完整安装器。

`python reinstall_v3/run_tests.py`：200项回归和20个核心场景通过。同一模拟首次
完整换蜂216→143次组件调用，同批后续换蜂104次；不是实际游戏秒数。覆盖元数据
复用、暂停输出变化、阶段缓存失效、重启全槽检查、缓存存在时不明搬运仍不重放。
实机在全部订单完成后的空闲窗口安装，保留备份、逐字回读和状态证明；没有为测速
搬蜂或申请AE订单，新的实际耗时待下一批验证。
