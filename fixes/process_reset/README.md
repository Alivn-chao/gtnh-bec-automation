# V1 进程重置与配方跳转

用户要求旧轮次消耗未确认时不要卡住服务，按当前配方继续；诊断只上传最近几次日志。`patch_v1.lua` 对游戏现有 V1 文件作定位补丁，不用本地旧完整控制器覆盖游戏文件。

安装时生成唯一 `.before-next-N` 备份，检查语法和写入回读；替换失败还原原文件。补丁修改 `/home/bec_auto.lua`、`bec_ui.lua` 和已有 `bec_upload.lua`，不启动机器或修改日志。重复安装不重复备份。节点须暂停15，纠缠装置关闭且不活跃。

```sh
lua /home/bec_patch_next.lua
lua /home/bec_ui.lua reset
```

`reset` 是明确的重新启动入口：先核对两份日志没有 pending、配置占用、未完成 AE 原液申请或不完整搬液，检查子网没有在途原液，然后把生产/缓存日志归档为 `.reset-N`；保留蜂群IO日志、场内库存、配置、配方记录及现有成品订单。新进程按当前订单和实际库存计算，不比较旧 target 或重放旧操作。已确认但未完成转换的历史目标不作为新进程的库存门槛。此命令会进入正常生产流程，不是只读预览。

节点进入 idle 而旧轮次消耗未确认时，记录 `lastOutcome.status=unconfirmed-or-skipped`，暂停后重新等待订单；它不判定成品成功，也不重新下发丢失的成品订单。用户可自行取消失效的 AE 成品任务。正常配方变化仍由外层流程读取当前需求、核对过滤、准备库存。蜂群等级变化后保持暂停并返回外层核对，不直接沿用旧过滤放行。

此补丁不修复机器内已经失败的配方，不提供跨设备原子状态采样，也不证明高速连续配方切换没有路由竞态。检测到未确认真实搬料/申请、供电或组件故障时仍停止；不通过丢弃在途记录制造重复请求。

精简上传默认 `recent`：当前 Lua、配置、当前 journal、`.previous`，每种 journal 最近两份数字编号归档；按文件修改时间排序，时间相同时按序号排序。原程序备份和配方目录不再默认上传。完整历史仅显式 `full` 上传，`status/ioport` 保留。

测试使用 Lua5.2 执行真实上传的 V1 控制器/UI补丁、安装回退/重复安装和完整模拟生产流程；覆盖旧目标库存不足重置、部分消耗 idle 后继续、双日志先核对后归档、在途请求不重放。上传测试覆盖90份历史只取最新两份、只读组件方法与 HTTP 失败处理。游戏安装和生产尚待用户实机验证。
