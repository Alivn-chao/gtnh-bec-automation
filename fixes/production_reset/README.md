# 未成功生产申请的重置

现场用户已确认：旧 `pipeline-converting` 的巨额原液申请没有成功。旧程序把尝试申请留下的 `submitted` 当作必须等完成的任务，正常 resume 和缓存 Z 都无法处理。

`patch_v1.lua` 在已装缓存重置 V3 的 V1 面板中增加生产分支，按钮改成 **Z 确认未下单 / 重置**。点击或键盘 Z 就表示用户确认本轮未完成的原液申请没有成功；无需全部主网 CPU 空闲，也不凭不可读 CPU 任务猜测提交结果。T 保留正常核对恢复。

安装时仅备份并修改 `/home/bec_ui.lua`，不修改控制器、蜂群模块、配置、生产日志或机器。先 Q 退出，再下载运行补丁，启动 `lua /home/bec_ui.lua resume`，在停止的故障页点击 Z。沿用原有故障调度，成功后自动进入 resume；控制器仍运行时不会另起重置任务。后台缓存阶段继续使用缓存 V3 的处理。

生产分支要求节点暂停 15、节点处于安全停止状态、纠缠器关闭且不活动、约束场开启、主网供液配置 0..5 全空。当前生产记录须有 plan/pipeline，不能有 pending 搬液、接口归属或未完成换蜂；历史搬液须完整确认。未完成申请须为旧 submitted，或有明确提交前失败标志的 rejected。

处理顺序：

1. 完整复制原生产日志到 `/home/bec_auto.journal.before-failed-reset-N`，保存独立 `.failed-reset` 进度和现场需求/消耗快照。
2. 仅转换已确认搬入子网、归属于本轮计划的整批余液，不搬新料、不申请 AE、不取消任务。核对约束场库存加子网原液守恒；Q、超时或核对失败关闭纠缠器，保留原日志和转换进度，下一次 Z 只接续剩余转换。
3. 原申请原文保存在备份和新 `retainedRequests`，标明 `user-confirmed-not-submitted`，申请本身的 state 不改成 done。已经 done 的申请保留。放弃旧 plan/pipeline，生成 watching 记录，原子替换并回读。
4. 原控制器 resume 归档此记录，按当前实际配方和库存重新计算缺口。新的自动申请失败提示用户手动补料，由已有 CPU/手动申请补丁负责；本补丁不重下旧巨额计划。

已确认搬入的料和场库存保留，缓存单项目标不改。后续独立失败会先备份上一轮已完成的重置进度，再开新轮；尚未完成的进度不得给另一份日志复用。未确认搬液仍显示具体原因，不盲目重放。

`reset.lua` 也可独立运行：`lua /home/bec_production_reset.lua confirmed-not-submitted`，成功后手动启动 UI resume。该参数同样表示用户明确确认这些未完成原液申请没有成功。

运行 `python fixes/production_reset/build_patch.py` 生成单文件安装器；`test_reset.py` 使用 Lua 5.2 模拟确认/无确认、原申请归档、库存保留、后续重置、进度归属、未知搬运/活动节点拒绝、中断/部分转换接续、替换回滚、真实控制器 resume 不重下旧单、最新 UI 安装幂等和鼠标 Z 自动继续。16 项通过；尚未游戏实测。
