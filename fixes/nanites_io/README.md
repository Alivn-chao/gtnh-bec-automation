本轮只验证一张数字奇点盘与蜂群仓的装入、回收，不替换 `/home/bec_nanites.lua`，不启动生产。使用独立 `/home/bec_nanites_io_test.journal`；旧蜂群日志即使仍为 filling 也只保留，不重放。

用户实际布局：转运器 `13070035-3a3f-4468-b896-1c084288fdc9`，南3硬盘→蜂群收容网，北2收容网→硬盘，底0硬盘盒。南红石 `4e31083a-e153-40e4-bf3f-e5ada363819d`；唯一另一个新增红石 `4bfbed4a-5d62-4311-9d34-5761103e76ce` 作为北端候选，通过回收测试核对。用户确认两只红石均在对应端口上方，向下0输出。

2026-10-11 实际只读上传：底盒243槽，第9槽19612个 Transcendent Metal Nanites（`gregtech:gt.metaitem.03`，damage4581，T4），第1..8槽为空盘。南北端口12槽全空，节点需求T1/蜂群0/isWorkAllowed=false，暂停红石向上15。驱动的 `getStackInSlot` 直接提供 `storedItemCount` 和 `getAvailableItems`，无需靠盘名猜内容。盒内129..243槽未在这次上传采样，测试只操作指定第9槽。

## 游戏端设置

- 两端都装1张红石卡、2张超光速卡，设“有红石信号时工作”。不使用常开或无信号工作。
- 南口“存储盘→网络”，建议“清空后移出”；北口“网络→存储盘”，“工序完成后移出”，不能等数字奇点装满。
- 两端只连接蜂群收容子网，该子网通过存储总线暴露蜂群仓；不能另连主网、备用大库或其他可存物品的位置。
- 保持传送节点 isWorkAllowed=false，暂停控制红石15；约束场保持开启。别运行生产UI或旧蜂群测试脚本。

## 下载与逐步测试

下载到新文件 `/home/bec_nanites_io_test.lua`，运行：

```sh
lua /home/bec_nanites_io_test.lua preview
lua /home/bec_nanites_io_test.lua load
```

默认第9槽，也可追加槽号，如 `load 9`。此版只支持上述T4蜂群，装入要求仓内为空、盘内1..30720且T4满足当前配方需求。OC仅搬一张盘到南口输入槽1，AE批量转移盘内蜂群；盘到输出槽7..12后关闭红石，核对空盘与仓内数量/等级，再搬盘回原盒槽，节点保持暂停。

装入真实成功后，再运行：

```sh
lua /home/bec_nanites_io_test.lua return
```

只回收本脚本上次成功装入的同一槽盘和数量，借此验证北端红石地址、网络与方向。不能用此测试直接接管任意原有蜂群。完成后，满盘应回到第9槽、蜂群仓0、两端IO全空、两端红石0。

每次搬盘前写入并回读意图，成功后核对两边槽位。已完成记录进入下轮前保留独立 `.before-run-N` 备份。部分转移、搬盘响应丢失、写盘失败、超时、手动开机或需求变化均停止；尽力独立关闭两端红石，盘和日志留在现场，不自动重试。报错后不要删除日志或重跑。正常的节点缓存延迟允许在端口停止后等待数量同步，不用非原子读数直接断言丢料。

此阶段不做自动等级选择、已有蜂群追加或超量盘分流。数字奇点盘超过30720时直接拒绝装入；不能等超光速搬运后再靠轮询截断。

`test_io.py` 的12个Lua5.2模拟场景覆盖装入/回收各两次单盘搬运、30720上限、只读预览、节点缓存延迟、部分转移不重放、响应丢失、日志写入失败、手动开机中断及保留旧日志。模拟不等于游戏硬件验收，南北槽位索引和实际红石控制效果需用户逐步测试。
