# 缓存并行下单与独立收料

原后台每次只挑一种凝聚物补库，等待该种原液申请、收料及转换后再挑下一种。
现在一次选取所有未达目标的已登记类型，按空闲 AE CPU 数提交独立请求，规划中的
请求预留名额。CPU 只有一台时自动排队；等待一种原液不妨碍收取其他已到账原液。
每种仍按现有目标补足缺口，单笔申请和实际转运受 int32 上限约束。

流体状态共用一轮库存/请求扫描，CPU 容量每波只读一次，等待日志仅在状态改变时
落盘。纯等待的整组地址/磁盘/节点状态检查最多每秒一次；真正搬液、启停纠缠器及
新一波申请仍使用新鲜检查。原料到达立即通知内存取消，停止提交完整的新补库任务，
已提交任务确认结束、零散原液补齐转换单位后交回生产。

每笔请求仍有写前记录；未知回复/取消不自动重放，明确提交前失败保留手动供料状态，
其他类型继续。每笔搬液仍核对回执及实际子网增量。AE 活句柄只留工作器内存，不能
写进持久计划；重启时未确认的申请仍需核对。

实现需要三个模块：`lib/cache_pipeline.lua`、`lib/cache.lua`、`runtime/cache.lua`。
旧六文件响应更新包没有新增的 pipeline 模块，不能当成本功能的完整安装器；缺模块
时保留原串行行为。通过 MCP 更新现有机器后正常重开网页即可使用，不需改缓存目标。

260 项回归及 20 个核心场景通过。新增十项覆盖三种同时申请/异步收料、一/两台 CPU
规划预留、失败互不阻塞、取消/未知回复保留、原料优先、暂停变化、旧包兼容，以及
相同 16 节点模型前后对照：3/5/8 秒的三笔 AE 任务，旧后台跨度约 32 秒、新版 8 秒；
节点/红石读取约 1 万次降至 1616 次。数字是模拟假设与调用量，不是实机秒数。

实机先等待原缓存完整收尾，确认 16 台 idle/关闭接单/暂停后退出唯一网页。
MCP 版本条件写入三模块、保留备份、逐字回读；Lua 编译与现场状态通过，配置不改。
证明在 `/home/bec_v2/diagnostics/cache-parallel-installed-20261027.dat`。
原有运行状态恢复，沿用用户实际补库目标；没有为了测速额外下测试订单。
