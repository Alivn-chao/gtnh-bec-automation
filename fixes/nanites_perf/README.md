# 临时换蜂计时

这是测试启动器，不是安装补丁。不覆盖 `/home/bec_auto.lua`、`bec_nanites.lua` 或 UI，不添加额外搬盘，也不改变正常换蜂的暂停策略。它在内存中给当前快速换蜂模块加计时，然后启动原 UI 的 resume 模式。正常生产、换蜂和原日志记录仍由原程序执行。退出时恢复 loadfile；下次直接启动 UI 就没有计时。

先等当前换蜂完成、IO 两端盘回盒后，按 Q 退出原程序。不要同时开两个控制程序。

下载本目录 `run.lua` 为 `/home/bec_nanites_perf.lua`，执行：

```sh
lua /home/bec_nanites_perf.lua resume
```

正常运行至少一次换蜂。等换蜂完成再 Q 退出，查看：

```sh
cat /home/bec_nanites_perf.txt
```

报告保留本次运行最近十次换蜂，包括失败交换。没有实际换蜂的库存复查不写报告；如果这次没有换蜂，旧报告不会清除，终端会提示没有新报告。

- 每阶段显示次数、含子步骤耗时、自身耗时。只有自身耗时可以相加；另加“决策及其他”应等于总耗时。
- 回收/装入包含搬盘、日志和 IO；ME IO 阶段包含等待盘完成及数量同步。“轮询等待及界面回调”另列，不能把整个 IO 阶段当成纯硬件传输时间。
- 库存扫描包括批量 reader.count/getAll、元数据补读和本地处理。组件调用列表仅计显式 component.invoke；reader 内部调用归入所在阶段。
- 日志读取/写入含回读是子项，已包含在阶段耗时里，不能再次相加。
- 报告写入发生在计时结束后，不计入总耗时；报告保存失败不改写正常交换结果。
- 保留原错误和未确认转移记录，不自动重试。测试脚本没有新增节点、GEN 或 IO 输出操作。

计时包装有少量执行开销，因此用来定位主要耗时，不是零开销基准。Lua 5.2 模拟测试核对真实模块的四次搬盘、数量、分段求和、等待回调、失败不重放、源文件保留和无换蜂不写报告；不是游戏硬件测试。
