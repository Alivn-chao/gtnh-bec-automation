# BEC 地址绑定工具

下载 [bec-binding.html](bec-binding.html)，双击用浏览器打开。单个文件即可离线使用，无需安装，也无需在游戏终端粘贴 Lua 代码。

1. 点击 4×4 网格中的位置，填写传送节点组件和这一组红石 I/O 的完整地址，再选择红石暂停输出方向。
2. 按实际位置从近到远一组一组填写。没有节点的位置留空；后续位置编号保持不变。仅填写一个地址会提示补全。
3. 填写公共主网、原液子网、约束场、麦克斯韦门、供液转运器和至少一台纠缠器。高速工业转运器可填 0–5 台，其他组件按需要填写。蜂群的转运器、备用接口、收容接口必须一起填写。
4. 点击“检查配置”。地址需为完整 UUID，不能只填前八位；工具检查格式、重复地址、方向和字段完整性。
5. 点击“保存草稿文件”下载 `bec-bindings.json`。之后用“打开草稿”继续修改。浏览器也会自动保存，但搬文件、换浏览器或清理浏览器数据后可能无法找回，因此建议下载草稿。
6. 点击“导出 V2 配置”，下载 `bindings.generated.dat`。

“批量填节点”支持每个位置一行：节点地址、红石 I/O 地址、可选方向（0–5）。用逗号、空格或 Tab 分隔；空行或 `-` 保留空位。批量应用会替换全部节点表，公共组件保留。

## 地址与实际机器

填写适配器提供的**机器组件地址**，而不是适配器方块自身的地址。主网、子网应填对应 ME 接口组件地址。转运器和红石 I/O 填它们各自的组件地址。

网页不连接游戏，不会查询设备类型、接线方向、距离或实际在线状态。4×4 网格用于记住绑定位置，不是机器结构图。方向编号：0 下、1 上、2 北、3 南、4 西、5 东。

## 导出的配置如何使用

导出表符合本仓库 V2 配置格式；一个共享公共设备组下最多 16 个节点。空位置不进入活动节点列表，节点名称与额外 `slot/row/column` 字段保留原位置。多个独立 BEC 网络需通过 V2 配置向导分别建立设备组。

导出不会自动激活配置，也不会改动旧 V1 的固定地址。已有 V1 用户可先保存绑定草稿，安装 V2 后再使用；旧 V1 不能直接读取这份配置控制 16 台。

`bindings.generated.dat` 是待核对的配置草稿，不要在控制器运行或旧批次未完成时直接覆盖 `/home/bec_v2/config.dat`。V2 配置向导仍负责检查设备在线、组件方法、接线和未完成记录。当前网页没有一键传入游戏的通道。

## 验证

`node tools/test_bec_binding.cjs` 检查鼠标录入、空位编号、方向 0、重复地址、可选蜂群、自动保存、JSON 往返、错误导入、批量输入原子性、配置下载、移动布局和离线运行。需要 Playwright 与 Chrome；测试生成物写入忽略的 `work/` 目录。

导出样例另外已通过 Lua 5.2 解析及 V2 发布版/开发版实际 `config.validate(cfg, false)`，这属于离线格式验证，设备运行仍需游戏测试。
