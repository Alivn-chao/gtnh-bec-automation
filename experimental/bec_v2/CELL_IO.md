# V2：存储盘换蜂群（2026-10-12 测试版）

使用与 V1 已验证接法相同的硬盘盒、蜂群转运器、两只 ME IO 端口和两只红石 I/O。同一 BEC 网络的 1–16 台节点共用一套蜂群设备；所有组内节点暂停、全部纠缠器停止活动后才搬盘。备用蜂群放入数字奇点存储盘，程序按等级选择并整盘搬运；不按 30720 限量，节点显示封顶不等于真实实物数量。

默认方向：硬盘盒下0、装入端南3、回收端北2，两端红石向下0。两只 IO 端口均设置“工序完成后移动至输出口”，装入端设硬盘→网络，回收端设网络→硬盘。程序使用输入槽1和输出槽7–12，先确认两端12槽IO及盒容量。网页和游戏配置向导允许修改这五个方向。

## 安装

先正常退出 V1/V2 服务，确认没有待处理的蜂群搬盘或旧批次；保留全部日志。以下安装器只替换 V2 程序，保留配置、配方和进度，下载全部通过语法检查才开始备份替换。

```sh
wget -f https://fastly.jsdelivr.net/gh/Alivn-chao/gtnh-bec-automation@bec-v2-cell-io-preview-2026-10-12/experimental/bec_v2/install.lua /home/bec_v2_install.lua
lua /home/bec_v2_install.lua
lua /home/bec_v2/main.lua setup
```

在配置向导启用自动换蜂群，选择默认 `cell-io`。也可以用网页工具填写并导出配置草稿，在线检查后再启用；不要在服务运行或旧日志未完成时直接覆盖配置。旧 V2 的双ME接口模式仍支持 `me-interface`，无 `mode` 的旧配置按旧接口处理，不会自动改接法。

配置完先运行 `lua /home/bec_v2/main.lua monitor` 只读核对；退出后 `lua /home/bec_v2/main.lua pause` 暂停节点并关闭纠缠器和两端IO红石，等待纠缠器实际停稳，再 `lua /home/bec_v2/main.lua run`。约束场保持开启。V1 和 V2 不要同时控制同一设备。

## 中断与恢复

V2 存储盘日志独立保存到 `/home/bec_v2/state/group-N/nanites-cell.journal`，不会重放 V1 的日志。同组只有一个工作器换蜂群。装入前记录搬盘意图、搬后核对源和目标槽、端口处理完核对盘内清单和蜂群仓读数。回收确认仓内0，盘内真实清单用于核对实物总量。错误或中途退出关闭两端红石，保留未完成日志；不确定的搬盘和部分转移不会自动重试。

两种蜂群模式有未完成日志时不能相互切换；配置向导也拒绝修改未完成绑定。缺少蜂群、空回收盘、组内节点未暂停或共享仓读数不同会停下，处理现场后再核对，不删除日志盲目重跑。

## 验证范围

Lua5.2 模拟覆盖装入/回收/同型追加/换等级/多盘/超过读数封顶/未知饱和数量/部分转移/不明搬盘/Q中断；实际 V2 bridge 覆盖2台和16台共享仓只换一次、组内未暂停或纠缠器忙拒绝、各方向映射、旧模式日志拒绝切换、退出关闭两端IO。原有 V2 控制器和网页浏览器测试一起通过。V1 实物装入与回收接法已验证；新 V2 的多节点存储盘模式仍待游戏验收。
